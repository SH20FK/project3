БАГ #1 — КРИТИЧЕСКИЙ: Отрицательный hashCode → портал в GloomVoid улетает на нереальные координаты
Файл: src/main/java/com/project3/Project3Mod.java
Метод: tickGloomVoidPlayer
Проблема: player.getUuid().hashCode() возвращает отрицательное int.
  int hash = player.getUuid().hashCode();
  double vx = (hash % 1000) * 1000.0;  // если hash отрицательный — vx = -500_000
  double vz = ((hash / 1000) % 1000) * 1000.0;
Исправление: использовать Math.abs(hash) перед вычислениями.

БАГ #3 — КРИТИЧЕСКИЙ: WALL_THRESHOLD проверяется от абсолютного (0,0), не от спауна
Файл: src/main/java/com/project3/Project3Mod.java
Поле: private static final int WALL_THRESHOLD = 20_000;
Проблема: World Border центрируется на spawn-точке, но penalty:
  if (Math.abs(x) >= WALL_THRESHOLD || Math.abs(z) >= WALL_THRESHOLD)
использует абсолютные координаты. Если спаун на (3000, 0, 0) — в западном направлении стена на 17_000 от спауна вместо 20_000.
Исправление: хранить spawnX/spawnZ при старте сезона и проверять расстояние от них: Math.abs(x - spawnX) >= WALL_THRESHOLD.

БАГ #5 — ВЫСОКИЙ: SCHEDULED_TASKS O(n²) удаление — лаг на активной сессии
Файл: src/main/java/com/project3/Project3Mod.java
Метод: ServerTickEvents.END_SERVER_TICK регистрация, блок tick scheduled tasks
Проблема: CopyOnWriteArrayList + SCHEDULED_TASKS.remove(task) внутри for-each итерации.
Каждый remove() создаёт новую копию массива — O(n) на одно удаление. При 20+ игроках с horror effects задач накапливается сотни.
Исправление: собрать задачи на удаление отдельно:
  List<ScheduledTask> toRemove = new ArrayList<>();
  for (ScheduledTask task : SCHEDULED_TASKS) {
      if (--task.remaining <= 0) { task.action.run(); toRemove.add(task); }
  }
  SCHEDULED_TASKS.removeAll(toRemove);

БАГ #6 — ВЫСОКИЙ: addHappinessTicks() не кэпит значение, возможно переполнение
Файл: src/main/java/com/project3/state/Project3State.java
Метод: addHappinessTicks
Проблема:
  public void addHappinessTicks(UUID uuid, long ticks) {
      setHappinessTicksLeft(uuid, getHappinessTicksLeft(uuid) + ticks); // нет Math.min!
  }
grantHappiness() в Project3Mod.java правильно ограничивает MAX_HAPPINESS_TICKS = 120000,
но addHappinessTicks не ограничивает. Прямой вызов командой или другим кодом может уйти в переполнение.
Исправление: добавить Math.min(getHappinessTicksLeft(uuid) + ticks, MAX_HAPPINESS_TICKS_VALUE) — или вынести константу MAX_HAPPINESS_TICKS из Project3Mod в Project3State.

БАГ #8 — СРЕДНИЙ: applyCorruptedBiomeEffects содержит избыточную и всегда-ложную проверку
Файл: src/main/java/com/project3/Project3Mod.java
Метод: applyCorruptedBiomeEffects
Проблема: внутри метода стоит:
  if (world.getTime() % 100 != 0) return;
Но метод вызывается только из блока:
  if (server.getTicks() % 100 == 0 && state.getProgressLevel() > 0) { ... }
При нормальном потоке server.getTicks() % 100 == 0 совпадает с world.getTime() % 100 == 0, поэтому внутренняя проверка всегда false при входе в функцию — метод всегда возвращается немедленно, ни один блок НИКОГДА не деградирует!
Исправление: удалить строку "if (world.getTime() % 100 != 0) return;" из тела applyCorruptedBiomeEffects.

БАГ #10 — НИЗКИЙ: generatedProducerChunks cap 10_000 без предупреждения приводит к повторной генерации Producer блоков
Файл: src/main/java/com/project3/state/Project3State.java
Метод: markGeneratedProducer

      generatedProducerChunks.add(key);
