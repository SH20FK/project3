═══════════════════════════════════════════════════════════
ЧАСТЬ 1 — CameraShakeManager (клиент): переход на trauma + Perlin noise
═══════════════════════════════════════════════════════════

Создать новый файл:
  src/client/java/com/project3/client/CameraShakeManager.java

Старый подход (сумма синусов с фиксированной длительностью) заменить на алгоритм 
"trauma" из GDC talk "Math for Game Programmers: Juicing Your Cameras" 
(стандарт для screen shake в играх типа Source Engine/Unreal):

━━━ Принцип работы ━━━

1. Есть одна переменная trauma (float, 0.0 до 1.0) — "накопленный стресс камеры"
2. События НЕ запускают отдельную анимацию с длительностью, а ДОБАВЛЯЮТ к trauma:
   trauma = Math.min(1.0f, trauma + amount);
3. Каждый клиентский тик trauma естественно затухает:
   trauma = Math.max(0f, trauma - DECAY_RATE); // например DECAY_RATE = 0.02f за тик
4. Реальный угол тряски вычисляется каждый кадр как:
   shake = trauma² * maxAngle * perlinNoise(time * frequency + seedOffset)
   Квадрат trauma даёт нелинейность — слабый толчок почти незаметен, 
   сильный ощутимо швыряет камеру.
5. Используются ТРИ независимых шума (для pitch, yaw, roll) с разными seed/offset — 
   чтобы оси двигались не синхронно, а органично вразнобой.

━━━ Реализация Perlin noise ━━━

В Minecraft уже есть готовая реализация — используй существующий класс 
net.minecraft.util.math.noise.PerlinNoiseSampler или net.minecraft.util.math.random 
(проверь что доступно в 1.21.11 маппингах). Если не доступен напрямую как публичный API — 
реализовать простой 1D Perlin/Value noise самостоятельно (упрощённая версия, 
достаточно интерполированного случайного шума, не обязательно классический Simplex).

Простой вариант value-noise на замену, если готового Perlin нет под рукой:

private static float noise1D(float x) {
    int xi = (int) Math.floor(x);
    float xf = x - xi;
    float v0 = hashToFloat(xi);
    float v1 = hashToFloat(xi + 1);
    float smooth = xf * xf * (3f - 2f * xf); // smoothstep
    return v0 + (v1 - v0) * smooth;
}

private static float hashToFloat(int i) {
    int h = i * 374761393;
    h = (h ^ (h >> 13)) * 1274126177;
    h = h ^ (h >> 16);
    return (h & 0xFFFF) / 65535f * 2f - 1f; // -1..1
}

━━━ Публичный API класса ━━━

public class CameraShakeManager {
    private static float trauma = 0f;
    private static float time = 0f;

    private static final float DECAY_RATE = 0.02f;   // затухание за тик
    private static final float MAX_ANGLE = 4.0f;      // максимальный угол в градусах
    private static final float NOISE_FREQUENCY = 0.6f;

    // Добавить толчок (можно вызывать много раз подряд — суммируется, капается в 1.0)
    public static void addTrauma(float amount) {
        trauma = Math.min(1.0f, trauma + amount);
    }

    // Вызывать каждый клиентский тик
    public static void tick() {
        trauma = Math.max(0f, trauma - DECAY_RATE);
        time += 1f;
    }

    public static boolean isActive() {
        return trauma > 0.001f;
    }

    // Вызывать из MixinGameRenderer.bobView() каждый кадр
    public static void applyShake(net.minecraft.client.util.math.MatrixStack matrices, float tickDelta) {
        if (trauma <= 0.001f) return;

        float shakeAmount = trauma * trauma; // нелинейность

        float t = time + tickDelta;
        float pitch = MAX_ANGLE * shakeAmount * noise1D(t * NOISE_FREQUENCY);
        float yaw   = MAX_ANGLE * shakeAmount * noise1D(t * NOISE_FREQUENCY + 100f);
        float roll  = MAX_ANGLE * shakeAmount * noise1D(t * NOISE_FREQUENCY + 200f);

        matrices.multiply(new org.joml.Quaternionf().rotationZ((float) Math.toRadians(roll)));
        matrices.multiply(new org.joml.Quaternionf().rotationX((float) Math.toRadians(pitch)));
        matrices.multiply(new org.joml.Quaternionf().rotationY((float) Math.toRadians(yaw * 0.3f))); // yaw слабее
    }

    private static float noise1D(float x) { /* см. выше */ }
    private static float hashToFloat(int i) { /* см. выше */ }
}

━━━ Подключение к рендеру ━━━

В существующем Mixin на GameRenderer (или создать новый MixinGameRenderer если его 
ещё нет — проверь есть ли уже инжект в bobView, судя по GameRendererAccessor он скорее 
всего частично готов), добавить вызов:

@Inject(method = "bobView", at = @At("TAIL"))
private void onBobView(MatrixStack matrices, float tickDelta, CallbackInfo ci) {
    CameraShakeManager.applyShake(matrices, tickDelta);
}

Тикать CameraShakeManager.tick() из клиентского ClientTickEvents.END_CLIENT_TICK 
(в Project3Client.java, там где уже наверняка есть другие клиентские тики).

ЧАСТЬ 2 — Сетевой пакет для синхронизации тряски сервер→клиент
═══════════════════════════════════════════════════════════

Создать payload по аналогии с существующими (AchievementSyncPayload, 
PlayerStateSyncPayload — посмотри их структуру и повтори паттерн):

  src/main/java/com/project3/network/CameraShakePayload.java

record CameraShakePayload(float traumaAmount) implements CustomPayload {
    public static final CustomPayload.Id<CameraShakePayload> ID = 
        new CustomPayload.Id<>(Identifier.of("p3", "camera_shake"));
    public static final PacketCodec<RegistryByteBuf, CameraShakePayload> CODEC = 
        PacketCodec.tuple(PacketCodecs.FLOAT, CameraShakePayload::traumaAmount, CameraShakePayload::new);

    @Override
    public Id<? extends CustomPayload> getId() { return ID; }
}

Зарегистрировать payload в общем месте регистрации (там же где AchievementSyncPayload 
регистрируется — и на CLIENTBOUND, и как S2C).

На клиенте в ClientNetworkHandlers.java добавить обработчик:
  ClientPlayNetworking.registerGlobalReceiver(CameraShakePayload.ID, (payload, context) -> {
      context.client().execute(() -> CameraShakeManager.addTrauma(payload.traumaAmount()));
  });

Вспомогательный метод на сервере (в Project3Mod.java или отдельном NetworkHelper) 
для рассылки всем игрокам сразу:

public static void sendShakeToAll(MinecraftServer server, float amount) {
    for (ServerPlayerEntity player : server.getPlayerManager().getPlayerList()) {
        ServerPlayNetworking.send(player, new CameraShakePayload(amount));
    }
}

В метод trigger(), внутри существующего цикла по тикам (тот что уже растягивает замену

━━━ Не одна тряска на всё событие, а серия нарастающих толчков ━━━

Внутри цикла "for (int tick = 0; tick < CORRUPTION_TICKS; tick++)", в теле

    // Толчки землетрясения — редкие в начале, частые и сильные к концу
    float progressRatio = currentTick / (float) CORRUPTION_TICKS;
    float shakeChance = 0.02f + progressRatio * 0.15f; // от 2% до 17% шанс за тик
    
    if (new Random().nextFloat() < shakeChance) {
        float shakeStrength = 0.15f + progressRatio * 0.5f; // от 0.15 до 0.65 trauma
        Project3Mod.sendShakeToAll(server, shakeStrength);
    }

За 2 секунды (40 тиков) до fake disconnect — один мощный финальный толчок:

    if (currentTick == CORRUPTION_TICKS - 42) {
        Project3Mod.sendShakeToAll(server, 1.0f); // максимальная тряска
    }

ЧАСТЬ 4 — Партиклы: огненные кольца вокруг корраптящихся блоков
═══════════════════════════════════════════════════════════

В том же цикле в trigger(), после замены каждой пачки блоков (chunk), для каждого 
игрока в радиусе спавнить расширяющееся кольцо частиц — визуализация "волны порчи".

Добавить метод:

private static void spawnCorruptionRing(ServerWorld world, double cx, double cz, float progressRatio) {
    // Радиус кольца растёт вместе с прогрессом события
    double ringRadius = 5 + progressRatio * (RADIUS - 5);
    int points = 24;

    for (int i = 0; i < points; i++) {
        double angle = (2 * Math.PI * i) / points;
        double px = cx + Math.cos(angle) * ringRadius;
        double pz = cz + Math.sin(angle) * ringRadius;
        int py = world.getTopY(Heightmap.Type.WORLD_SURFACE, (int) px, (int) pz);

        world.spawnParticles(
            net.minecraft.particle.ParticleTypes.FLAME,
            px, py + 0.5, pz,
            1,       // count
            0, 0.05, 0, // dx dy dz
            0.01     // speed
        );
    }
}

Вызывать раз в 10 тиков (не каждый тик — иначе перегрузка партиклов):

    if (currentTick % 10 == 0) {
        spawnCorruptionRing(world, cx, cz, progressRatio);
    }

(cx, cz уже вычислены в начале trigger() — использовать существующие переменные, 
не пересчитывать).

ИТОГ ПОВЕДЕНИЯ
═══════════════════════════════════════════════════════════

Первые секунды события — редкие слабые толчки (2% шанс/тик, trauma 0.15-0.2), 
почти незаметные. К концу 30-секундного окна — толчки учащаются (до 17% шанс/тик) 
и усиливаются (trauma до 0.65). За 2 секунды до дисконнекта — один резкий сильный 
удар (trauma 1.0, максимальная тряска). Параллельно вокруг игроков расширяются 
огненные кольца частиц, радиус растёт вместе с прогрессом замены блоков — видно 
как "волна порчи" физически накрывает территорию.
